Beginner guide

Never sold a ticket? You are four ideas away.

Railway software sounds specialised. The model underneath is simple, and everything in RailFlow is built from these four ideas.

01

A workspace is one company's private office

Every company gets its own users, trains, bookings, branding and plan. Nothing is shared. When you sign in with a workspace slug, you are choosing which office door to open.

02

A train is not a departure

The train is the vehicle — name, route, seat layout. The schedule decides which days it runs. Inventory is counted per train and per date, so Tuesday can be sold out while Wednesday is empty.

03

A booking is one reservation, one PNR

The PNR is the short code a passenger quotes at the desk. A booking carries the journey, the passengers, the seats and the money — and it can be confirmed, changed or cancelled.

04

Inventory is the source of truth

Available seats are not typed in by hand. They are derived from capacity minus live bookings. Checkout locks the inventory row, which is why the last seat can only be sold once.

Quick start

Run the whole thing in 60 seconds.

Docker is the only prerequisite. The stack starts PostgreSQL, the API and the web app, then seeds three workspaces with data you can explore.

Three commands, one demo

From the repository root:

$ cp .env.example .env
$ make up
$ open http://localhost:8080
First build takes a few minutes. Later starts are seconds.

HTTPS is available on https://localhost:8443. To stop everything: make down. To reset the data: make down then make up.
